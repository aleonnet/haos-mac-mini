# PLANO F5–F10 — haos-install.sh v0.3.0 (v1, pré-banca)

Norte: o leigo roda UM comando e termina com o endereço real do HA na tela e o
navegador aberto. Idempotente (0/100/1 por fase), manifesto, uninstall inverso,
cerca no portão para cada fase. bash 3.2, `set -Eeuo pipefail`, curl|bash.

Fases novas (HA_BAR_TOTAL real: 5 → 10; dry-run continua 3):

## F5 — fase 06 "Boot" (fase_boot)
- Já rodando E respondendo → 100. Senão `vbm startvm <nome> --type headless`.
- Espera pelo MAC, nunca pelo .local: `showvminfo --machinereadable` →
  `macaddress1` (0800270C0FFB) → formato arp (8:0:27:c:f:fb — sem zeros à
  esquerda, minúsculo) → laço: ping broadcast p/ popular ARP → `arp -an` → IP
  → `curl -m3 http://IP:8123/` até 200/302. Timeout `HAOS_BOOT_TIMEOUT` (900s,
  seam p/ cerca), passo 5s, `ha_bar` em segundos.
- Grava `vm_mac`/`vm_ip` no manifesto (bookkeeping). IP é dinâmico — toda
  leitura posterior refaz a descoberta se o curl no IP gravado falhar.
- Cerca: stubs VBoxManage/arp/curl/ping; convergência, IP no manifesto,
  caminho de timeout com HAOS_BOOT_TIMEOUT=1.

## F5b — mesma fase 06 (auto-start)
- Desired-state: `~/Library/LaunchAgents/com.haos-mac-mini.<vm>.plist` com
  `/bin/sh -c 'VBoxManage list runningvms | grep -q "<vm>" || VBoxManage
  startvm <vm> --type headless'` usando caminho COMPLETO do bundle (launchd
  não tem /usr/local/bin — lição de hoje). Gerar em tmp → cmp → install →
  `launchctl bootstrap gui/$(id -u)` (fallback `load -w`). Manifesto host:
  `launchagent` created/preexisting + path. Igual → 100.
- Uninstall: `launchctl bootout` + rm guardado (classe nova em
  un_caminho_seguro: `$HOME/Library/LaunchAgents/com.haos-mac-mini.*`).

## F6 — fase 07 "Conta" (fase_conta)
- `GET /api/onboarding` (helper Python): users pendente → pedir NOME DE
  USUÁRIO (default do dono da máquina) e SENHA (2x, nunca ecoada, nunca em
  argv, nunca no log) — lazy: só pergunta se o passo está pendente. Headless:
  env `HAOS_HA_USER`/`HAOS_HA_PASSWORD`; ausentes sem TTY → erro claro.
- Sequência (contract/check.py já prova o shape): POST users → auth_code →
  POST /auth/token (form) → access_token; POST core_config; POST analytics
  (consentimento NÃO assumido — enviado desligado); POST integration.
  Pós-condição: GET /api/onboarding → concluído/404.
- Onboarding já feito → 100; para F7+ autenticar via login_flow (mesmo shape
  do check.py) com as mesmas credenciais pedidas.
- Token só em memória + env do helper. Nada persistido.
- Helper: `lib/ha-api.py` (fonte) EMBUTIDO no instalador via embed.sh
  (novo bloco marcado, com drift-check no portão e no CI, como o catálogo).
- Cerca: servidor HTTP fake (python http.server) no portão simulando as rotas
  de onboarding; asserta sequência e pós-condição.

## F7 — fase 08 "Apps" (fase_apps)
- Cliente WebSocket RFC6455 mínimo em stdlib no helper (handshake + máscara +
  frames de texto + PING/PONG). Auth → `supervisor/api` {endpoint, method}.
- Por item selecionado com slug de app: repo_terceiro → POST
  /store/repositories e DESCOBRIR o prefixo hash via GET /store/addons por
  nome (nunca fixar). POST /store/addons/<slug>/install → poll
  GET /addons/<slug>/info até version instalada (timeout generoso) → options
  quando obrigatório → start → pós-condição state=started.
- samba: options {username: haos, password: GERADA} — senha aleatória, só em
  memória + relatório final (é credencial de LAN do próprio usuário).
- advanced_ssh: authorized_keys=[chave ed25519 gerada em
  `~/.ssh/haos-mac-mini(.pub)` se não existir] — dá SSH ao dono sem senha.
- 0/100 por app (instalado+started → 100).
- Cerca: servidor WS fake no portão (mesmo RFC, lado servidor, ~60 linhas)
  respondendo supervisor/api; asserta sequência install→info→start e o
  descobrimento do prefixo hash.

## F8 — fase 09 "Integrações" (fase_integracoes)
- Regra da curadoria §23: popularidade ≠ instalação automática; NUNCA pedir
  credencial de serviço. Só completa flow SEM dado do usuário:
  - systemmonitor: POST flow {handler} → step user → POST {} (schema vazio).
  - workday: schema_flow — ler o schema devolvido e preencher só defaults.
  - mqtt: com mosquitto:ha instalado pela F7, o flow hassio se resolve — não
    duplicar por fora (regra `:ha` do catálogo).
- Demais (hue/tuya/broadlink/shelly/tplink/smartthings/cast/...): contar flows
  de discovery em progresso (GET flows) e REPORTAR "N descobertas esperando
  você no painel" — criar entry com credencial é proibido.
- CERCA DE CONJUNTO do catálogo: toda entry criada → ler de volta e conferir
  `source ∈ setup`. Reprova = remove a entry e falha a fase.
- Cerca no portão: fake REST server com flows; asserta a cerca de conjunto
  reprovando um source fora da lista.

## F9 — fase 10 "Arquivos" (fase_arquivos)

- configuration.yaml: linha-a-linha (disciplina do overlay Tapo): sem

- hacs (se selecionado): baixar hacs.zip da release oficial (SHA quando

## Decisões já tomadas (custo/reversibilidade)
1. Espera por MAC→ARP, não mDNS (falso positivo medido hoje). Reversível.
2. Packages via SMB, não SSH (samba já é requires; mount_smbfs é do macOS).
3. Senhas: HA pedida ao dono (lazy); samba gerada; nada persiste em disco
   além do plist (sem segredo) e da chave SSH (par local do usuário).
4. Token de API só em memória/env — reexecução pede a senha de novo.
5. F8 nunca toca credencial de serviço — flows ficam esperando no painel.
